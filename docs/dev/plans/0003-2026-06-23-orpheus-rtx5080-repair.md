# Plan 0003 | Orpheus RTX 5080 Repair

## Objective

Make the local Orpheus TTS service usable on the Cooper WSL host with an RTX 5080 while keeping Hugging Face credentials outside the repository.

## Investigation Plan

1. Prove whether the current failure is Hugging Face access, model download, vLLM startup, GPU memory pressure, or audio decoding.
2. Verify the installed CUDA/PyTorch/vLLM stack against RTX 5080 and WSL constraints.
3. Prefer `uv` for Python package installation and verification.
4. Keep service credentials in user-scoped runtime files with restrictive permissions.
5. Add a repo-owned fallback path if the upstream Orpheus/vLLM stack remains unstable on this host.

## Investigation Results

- Hugging Face Hub is installed as a repo dependency through `uv` and as a user tool exposing `hf`.
- The Cooper-specific Hugging Face token can access `canopylabs/orpheus-tts-0.1-finetune-prod`; the original 401 gated-repo error is resolved.
- The Orpheus service now starts in lazy-load mode and reports healthy until generation triggers model loading.
- The vLLM path progressed past authentication after adding the service token, but failed or stalled under RTX 5080 WSL conditions:
  - Initial GPU allocation was too high for available VRAM.
  - vLLM V1/V2 runner hit a WSL UVA failure path.
  - After disabling that path and constraining memory/model length, model load still stalled after selecting the Triton attention backend.
- Runtime evidence points to vLLM/Blackwell/WSL compatibility as the current blocker, not Open Notebook routing or Hugging Face authorization.

## Mitigation Plan

1. Keep the vLLM path available behind `ORPHEUS_BACKEND=vllm` for future CUDA/vLLM updates.
2. Add a first-class wrapper fallback with `ORPHEUS_BACKEND=transformers` using:
   - `transformers.AutoModelForCausalLM`
   - the same Orpheus prompt tokens used by the upstream package
   - the installed `orpheus_tts.decoder.tokens_decoder_sync` SNAC audio decoder
3. Configure the live user service to use the Transformers backend on Cooper.
4. Validate:
   - repo dependency import for `huggingface_hub`
   - Python syntax and ruff for the wrapper
   - service health after restart
   - short `/v1/audio/speech` generation if the model loads within available VRAM

## Acceptance Criteria

- `uv run python -c 'import huggingface_hub'` succeeds.
- `hf` is available from the `uv tool` installation.
- `/health` reports the selected Orpheus backend.
- A short request to `/v1/audio/speech` returns non-empty audio, or the remaining blocker is captured with logs and service health restored.

## Follow-Up

- Keep `ORPHEUS_BACKEND=vllm` as an optional future path after vLLM/WSL/Blackwell support improves.
- If Transformers latency is too high for interactive use, test a quantized GGUF Orpheus backend or an isolated newer vLLM CUDA wheel in a separate runtime before changing the live service again.
