## Goal

Add a repo-owned OpenAI-compatible wrapper for the existing local Dia runtime so Dia can be registered in Open Notebook as a selectable `text_to_speech` model alongside Kokoro, Chatterbox, and Orpheus.

## Background

Plan 0004 registered the local OpenAI-compatible TTS services that already expose `/v1/audio/speech`:

- Kokoro: `kokoro-82m`
- Chatterbox: `chatterbox-tts`
- Orpheus: `orpheus-3b`

Dia was left out of Open Notebook model registration because the current Cooper unit starts the upstream Gradio app only:

```text
open-notebook-dia-tts.service
WorkingDirectory=/home/ecochran76/.local/share/open-notebook/tts/dia/repo
ExecStart=/home/ecochran76/.local/share/open-notebook/tts/dia/.venv/bin/python app.py --device cuda
Port: 18881
```

The installed Dia app loads `Dia.from_pretrained("nari-labs/Dia-1.6B-0626", compute_dtype="float16", device=cuda)` and exposes a Gradio function named `run_inference(...)`. The core generation path is direct Python:

```python
output_audio_np = model.generate(
    text_input,
    max_tokens=max_new_tokens,
    cfg_scale=cfg_scale,
    temperature=temperature,
    top_p=top_p,
    cfg_filter_top_k=cfg_filter_top_k,
    use_torch_compile=False,
    audio_prompt=prompt_path_for_generate,
    verbose=True,
)
```

The wrapper should reuse that core behavior without depending on Gradio request handling.

## Non-Goals

- Do not replace the existing Dia Gradio UI unless an implementation choice requires a coordinated service split.
- Do not register Dia in Open Notebook until the wrapper passes `/v1/models` and `/v1/audio/speech` smoke tests from inside `open-notebook-cooper`.
- Do not commit model weights, Hugging Face cache files, generated audio, runtime logs, or credentials.
- Do not make Dia the default TTS model in the first pass. Kokoro remains the default unless later quality/latency evidence justifies changing it.

## Target API

Add `scripts/local_tts/dia_openai_server.py` with:

- `GET /`
  - small browser UI for text, generation parameters, playback, and WAV download.
- `HEAD /`
  - ingress/browser health compatibility.
- `GET /health`
  - returns model id, upstream model, device, model-loaded state, load error, and default parameter values.
- `GET /v1/models`
  - returns OpenAI-compatible model list with id `dia-1.6b`.
- `GET /v1/audio/voices`
  - returns a minimal voice catalog. Dia is prompt/dialogue driven, so voices should be semantic aliases rather than pretending to be distinct trained speakers.
- `POST /v1/audio/speech`
  - accepts OpenAI-compatible text-to-speech fields:
    - `model`
    - `input`
    - `voice`
    - `response_format`
    - `speed`
  - accepts Dia tuning fields as optional extensions:
    - `max_tokens`
    - `cfg_scale`
    - `temperature`
    - `top_p`
    - `cfg_filter_top_k`
    - `seed`
  - supports response formats needed by Open Notebook / Esperanto:
    - `mp3`
    - `wav`
    - `flac`
    - `pcm`
- Optional later endpoint:
  - `POST /v1/audio/speech-form` for audio prompt uploads and voice-clone style Dia usage.

## Implementation Design

### Model Loading

Use lazy loading, matching the heavier Orpheus pattern:

- Keep `/`, `/health`, and `/v1/models` available before model load.
- Load Dia only on first generation or explicit warmup.
- Configurable environment:
  - `DIA_TTS_ROOT=~/.local/share/open-notebook/tts/dia`
  - `DIA_OPENAI_MODEL=dia-1.6b`
  - `DIA_MODEL_NAME=nari-labs/Dia-1.6B-0626`
  - `DIA_DEVICE=cuda`
  - `DIA_COMPUTE_DTYPE=float16`
  - `DIA_SAMPLE_RATE=44100`
  - `DIA_DEFAULT_VOICE=dialogue`
  - `DIA_MAX_TOKENS=1024` or another short default selected during smoke testing
  - `DIA_CFG_SCALE=3.0`
  - `DIA_TEMPERATURE=1.3`
  - `DIA_TOP_P=0.95`
  - `DIA_CFG_FILTER_TOP_K=45`

### Voice And Prompt Handling

Dia works best with dialogue markup such as `[S1] ... [S2] ...`. The wrapper should:

- Pass user input through unchanged if it already contains `[S1]` / `[S2]` markers.
- For plain input, wrap it as a single speaker:
  - `[S1] {input}`
- Map OpenAI voice aliases to safe Dia prompt styles:
  - `alloy`, `dialogue`, `default` -> single-speaker `[S1]`
  - `echo`, `ash`, `onyx` -> single-speaker `[S2]`
  - `coral`, `nova`, `shimmer` -> single-speaker `[S1]`
- Avoid claiming Dia has discrete trained voices.

### Audio Encoding

Dia returns NumPy audio at 44.1 kHz. Encode with `soundfile`:

- `mp3`: `audio/mpeg`
- `wav`: `audio/wav`
- `flac`: `audio/flac`
- `pcm`: raw float32 or int16 PCM, consistent with existing wrappers where possible.

Keep generated bytes in memory for API responses; do not write generated audio into the repo.

### Runtime And Service Strategy

Preferred first pass:

- Run the OpenAI wrapper on a new local port, e.g. `18884`.
- Keep the Gradio UI on `18881`.
- Register Dia in Open Notebook with `http://host.docker.internal:18884/v1`.

Reasoning:

- Two separate processes avoid disrupting the existing inspection UI.
- The wrapper can be validated independently before ingress/routing changes.
- If GPU memory pressure is too high with both processes loaded, update the service plan to run only one Dia process at a time or move Gradio behind the wrapper UI.

Alternative:

- Replace the existing Dia service with the wrapper and mount the Gradio UI separately later.
- Use this only if maintaining two Dia model instances is too expensive on the RTX 5080.

## Risks

- Running Dia Gradio and Dia OpenAI wrapper as separate processes may double-load the 1.6B model and exceed comfortable VRAM when Chatterbox/Orpheus are also active.
- Dia cold start may be slow; health should distinguish process availability from model-loaded state.
- Dia is dialogue-oriented, so OpenAI-style `voice` values are only aliases. Docs and UI must avoid implying separate voice models.
- Esperanto may request `response_format=mp3` and `voice=alloy`; the wrapper must tolerate both.
- The upstream Dia Gradio app parses CLI args at import time, so the wrapper should import `dia.model.Dia` directly rather than importing `app.py`.
